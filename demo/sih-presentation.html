Idea Title
@SIH Idea submission · Team Hexacore
Proposed Solution

An AI browser agent with an unbreakable privacy firewall. The cloud LLM reasons over fully redacted data and plans actions using placeholder references that only the browser can resolve to real values.

  • ✓On-device perception pipeline — DOM scanning, regex redaction, NER name masking, face blur, OCR masking run entirely in the browser before any data is sent.
  • ✓Placeholder Ref architecture — the server plans with tokens like [EMAIL_1], [PERSON_1]; real values exist only in a page-local map and never reach the network.
  • ✓8-layer defense — Regex → NER → ViT → Face Detection → OCR → DOM Blackout → Injection Guard → Server Guard.
How It Addresses the Problem
  • ✓Ends the all-or-nothing trade-off: users get full AI capability without exposing passwords, bank balances, or medical records to a cloud server.
  • ✓Proven on end-to-end demos: banking transfer and 15-field healthcare intake completed with 0 bytes of PII leaving the device.
Innovation & Uniqueness
  • ★Novel Placeholder Ref System — no prior work lets a cloud LLM plan with anonymized placeholders resolved only client-side.
  • ★Vision-first redaction — face detection on the raw frame catches what DOM parsing cannot see.
  • ★4 self-hosted ML models (ViT, BlazeFace, Tesseract, DistilBERT) running fully in-browser, offline-capable.
Technical Approach
@SIH Idea submission · Team Hexacore

💻 Client — Browser Extension

TypeScript + WXT (single codebase → Chrome MV3 + Firefox MV2) + React + ONNX Runtime Web. DOM extraction, redaction, OCR, and action execution all on-device.

Models (in-browser): ViT vision (ONNX/WASM) · BlazeFace (MediaPipe) · Tesseract.js OCR · DistilBERT NER

🖥 Server — FastAPI + Render

Python FastAPI with WebSocket gateway, rate limiter, and origin validation. Receives only anonymized payloads; returns action plans with placeholder refs.

LLM: OpenRouter — Nemotron 120B (free tier), 4-strategy JSON extraction fallback, graceful prose → fail handling.

Feasibility & Viability
@SIH Idea submission · Team Hexacore
Feasibility Analysis
  • ✓Zero-infrastructure — all ML runs in the browser via WASM; no GPU servers needed. Deployed on free Render hosting + free extension stores (Firefox AMO, Edge Add-ons).
  • ✓Working prototype — live end-to-end demos on banking + healthcare forms, server deployed at veil-agent.online, 15/15 automated tests passing.
  • ✓Offline-capable — self-hosted ViT model cached after first load; works without external model downloads.
Challenges & Risks
  • ⚠Large ML models (88MB ViT) — mitigated with ONNX quantization + self-hosting + browser caching after first load.
  • ⚠Free LLM JSON reliability — mitigated with 4-strategy JSON extraction fallback and graceful prose → fail handling.
  • ⚠Chrome MV3 offscreen limitation — solved with a hidden offscreen document running MediaPipe/Tesseract under watchdog timeouts.
  • ⚠Prompt injection attacks — 9-pattern scrubbing + zero-width char stripping, mirrored client-side and server-side.
  • ⚠Free tier cold starts — Render spins down after idle; mitigated with UptimeRobot monitoring pinging /health every 5 min.
Risks vs. Mitigations

🛡 Deployment at scale

Stateless, horizontally scalable FastAPI + WebSocket gateway; auth-token opt-in and rate limiting built in.

📈 Measurable outcome

Precision, recall, and IoU scored against labeled corpora in vitest — a repeatable, quantified CI pipeline.

Impact & Benefits
@SIH Idea submission · Team Hexacore

Target audience: privacy-conscious consumers, healthcare staff filling patient forms, banking users automating transfers, and anyone wanting AI assistance without a privacy trade-off.

👥 Social Impact

Protects users' most sensitive data — medical records, financial accounts, private messages — while enabling AI assistance. Makes AI agents accessible to privacy-conscious and vulnerable users.

💰 Economic Impact

$0 hosting cost (free Render tier + free extension stores). No premium API spend — runs on free LLM tiers. Reduces organizational liability and cost of data-breach incidents.

🌿 Environmental Impact

On-device processing reduces cloud compute and data-center storage of user screenshots. Energy-efficient — ML models load lazily only when a feature is used.

Demonstrated Benefit
🔒

Zero PII Leakage — proven in live demos

Banking transfer and healthcare intake completed end-to-end. Real values (email, phone, Aadhaar, name) existed ONLY in a page-local PlaceholderMap — the cloud server received only [REF] placeholders and a sanitized screenshot.
